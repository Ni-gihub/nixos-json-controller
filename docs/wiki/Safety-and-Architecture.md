# 安全性とアーキテクチャ

NXC は、CLI や GUI からの操作をそのまま設定ファイルへ書き込むのではなく、対象と変更内容を検証してから処理する構成を目指しています。

## パッケージ操作のおおまかな流れ

```text
ユーザー入力
    ↓
入力の解析・検証
    ↓
パッケージ名やサービス名の解決
    ↓
実行計画の作成
    ↓
対象となる NixOS 設定の変更
    ↓
Nix 評価
    ↓
nixos-rebuild switch
    ↓
変更後の状態確認
```

実際の処理は操作の種類や現在の configuration によって異なります。

## 設定を無条件に書き換えない

NixOS configuration は、単純な文字列置換だけでは意味を保てない場合があります。NXC は変更箇所を安全に特定できないと判断した場合などに、処理を拒否することがあります。

既存の設定構造が対応できず変更を拒否された場合は、エラー内容と対象ファイルを確認してください。安全判定を回避するためだけに検証を無効化したり、設定を手作業で単純置換したりしないでください。必要な構造への対応は Issue で管理します。

## dry-run

`--dry-run` は、変更前に実行計画を確認するためのオプションです。通常、設定変更とシステム再ビルドを行わず、予定内容の確認に使用します。

```sh
nxc i firefox --dry-run
```

dry-run は本番実行の成功や、すべての副作用がないことを保証するテスト環境ではありません。計画を確認し、対象が意図どおりであることを確かめてください。

## 変更後の検証と復元

パッケージの追加・削除では、再ビルド後にアクティブなシステム上の存在状態を確認します。検証に失敗した場合、NXC は設定の復元と必要な再ビルドを試みます。復元にも失敗した場合は、元のエラーと復元エラーの両方を確認してください。

サービスの有効化・無効化については、パッケージ操作と同等の再ビルド後検証が未対応の箇所があり、[Issue #138](https://github.com/Ni-gihub/nixos-json-controller/issues/138) で管理しています。すべての操作に同一の復元保証があるものとして扱わないでください。

## 権限

NixOS 設定の変更や再ビルドに必要な場合、sudo 認証が求められます。権限を求める操作の対象と実行計画を確認してから承認してください。
